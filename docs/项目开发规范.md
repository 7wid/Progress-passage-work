# 项目开发规范

> 更新：2026-09-12。以现有仓库为技术基线，面向开发、审查、测试与运维。

## 1. 文档与代码职责

业务能力和状态见[需求文档](需求文档.md)，协作、验收和发布见[项目流程书](项目流程书.md)，页面实现见[前端实现说明](前端实现说明.md)。本文集中规定编码、接口、数据和检查要求，启动命令只在[根 README](../README.md)维护。

先确认使用角色、输入输出、状态与资源权限再实现。沿用仓库中的同类代码；一项变更解决一个明确问题。已确认的新需求与验收条件必须同时落实到实现和文档，不能静默选择互相矛盾的一份说明。

## 3. Git 与依赖

- main 保存经审查和验证的实现。功能、修复、文档和维护使用短期分支，可用 feat/、fix/、docs/、chore/；已有 codex/ 任务分支遵循同样生命周期。
- 开始操作前检查工作区，保留其他任务的已修改和未跟踪文件；提交按实际范围选择文件或代码块。
- 提交格式为 `<type>(<scope>): <结果>`；PR 说明问题、最终行为、验证方式以及配置/迁移和兼容性影响。
- 删除分支前先 fetch --prune，检查相对 origin/main 的祖先关系、独有提交和 worktree 占用。只清理已合并或已证明等价的分支，不用强制删除绕过未合并提示。
- worktree prune 仅清理已失效登记；真实目录仍存在时先核对其中工作，不直接递归删除。
- 不改写共享分支历史，不提交 env、令牌、私钥、用户数据、备份、依赖或构建产物。
- 前端只使用 pnpm 并保留锁文件；后端只通过 pom.xml 和 Maven Wrapper 管理。核心依赖升级单独评估和回归，不删除锁文件或降低检查门槛来消除错误。
- 优先沿用标准 API 与现有依赖，新增依赖需要说明用途、维护情况、许可证与体积影响。

## 4. 通用代码与前端

UTF-8 编码。Vue 组件、Java 类、类型使用 PascalCase；函数和变量使用 camelCase，数据库表/字段使用 snake_case，常量使用 UPPER_SNAKE_CASE。前端已有普通 TS 文件采用 camelCase，按所在目录一致命名。注释解释约束和原因，不重复显然动作；错误必须处理，禁止空 catch 吞掉真实故障。

- Vue 使用组合式 API 与 script setup；API 函数放 src/api，响应类型放 src/types。
- Pinia 只承载认证、通知等跨页面状态；筛选、分页、编辑草稿和弹窗放页面局部状态。
- 不使用 any 绕过类型检查，不把后端 Long ID 转成 JavaScript number 做精确运算；接口 ID 保持字符串。
- 用户输入通过文本插值渲染，避免把需求说明、评估或附件名传给 v-html。
- 列表请求处理迟到响应，路由目标变化后不允许旧数据覆盖新页面。
- 表单从异步校验开始锁定重复写操作，使用输入快照；保存成功立即更新版本，提交失败保留输入。409 不自动覆盖最新版本。
- 未保存离页有提醒；网络错误不等于数据库回滚。当前不将需求正文、联系信息和恢复令牌放入浏览器持久存储。
- 需求方文案说明当前状态与下一步，技术评估和成员推荐只在合适角色中展示。
- UI 沿用 Element Plus 与 Lucide，品牌 Logo 复用 ProductLogo；键盘焦点、标签、错误提示和触控目标必须可用。
- 视觉令牌、路由、动画和响应式规则集中维护在[前端实现说明](前端实现说明.md)，不在本文件复制一套 CSS。

## 5. API 契约

路径前缀 `/api/v1`。Controller 负责 HTTP/DTO/鉴权边界，Service 负责业务及事务，Mapper 负责数据访问。Controller 不直接操作 Mapper；Entity 不直接作为响应暴露。操作者从认证上下文取得，不信任前端传入的 operatorId。

| 项目     | 当前约定                                                                                    |
| -------- | ------------------------------------------------------------------------------------------- |
| 成功响应 | `{ "data": ..., "requestId": "..." }`                                                       |
| 错误响应 | `{ "error": { "code": "...", "message": "...", "details": [] }, "requestId": "..." }`       |
| 字段错误 | details 中提供 field 与 message                                                             |
| 分页     | page 从 1 开始；pageSize 有上限，需求列表最大 100                                           |
| 时间     | 时间点采用 ISO 8601/UTC；日期字段采用 YYYY-MM-DD，业务日期按 Asia/Shanghai                  |
| 标识     | Long 主键对前端输出字符串；需求编号由后端生成                                               |
| 状态更新 | 使用现有 expectedVersion 或 requestVersion 字段，不混用字段名                               |
| 错误语义 | 400 输入错误、401 未登录、403 禁止、404 不存在/隐藏、409 冲突、429 限流；保持接口实际状态码 |

所有分页、排序、日期范围与输入长度都由服务端校验；排序采用白名单，SQL 使用绑定参数，不能拼接用户片段。避免 N+1 查询和先查全量再内存分页。接口变更同步修改 DTO、VO、前端类型、调用和测试；开发 OpenAPI 可查，生产默认关闭。

## 6. 状态、事务与并发

- 状态和角色使用枚举，禁止任意字符串更新；校验角色、资源、状态、输入和版本后才能写。
- 关键操作使用事务；状态、版本、审计和关联记录应保持原子性。行锁、条件更新及影响行数共同处理竞争，不以“前端按钮已禁用”代替并发保护。
- 保存内容与提交状态是两次请求，前端必须反映各自结果。不要承诺没有实现的全流程幂等。
- 分配唯一主负责人、参与者约束、最新交付一次验收等业务不变量由服务层和数据库共同维护。
- 通知在业务提交后处理；SMTP 使用独立有界队列，不能在持有数据库事务时等待外部邮件服务。
- 文件系统与数据库不能天然原子提交，附件沿用 pending/绑定及清理机制；失败时不得留下可公开下载的未授权文件。
- 时间相关测试使用可控输入或时钟，避免跨天、时区和窗口边界不稳定。

## 7. 认证、隐私与附件

- 统一 Spring Security Session + Spring Session JDBC，不增加并行 JWT 登录通路。
- Axios 携带会话 Cookie，写请求按现有 CSRF 握手获取并发送令牌；公开注册/密码恢复写接口同样不能绕过 CSRF。
- Session Cookie 使用 HttpOnly、SameSite=Lax，HTTPS 生产启用 Secure；CORS 仅允许配置的真实源。
- 后端每次受保护请求校验账号状态及必要的会话撤销条件；修改密码、重置密码、角色或启停用需保留相关回归。
- 账号/密码/令牌限制以 user/auth DTO 与配置为准。登录与找回响应不泄露账号存在性；找回限流和一次性凭证依赖数据库共享状态。
- 不记录密码、令牌、Session ID、完整邮箱、邮件链接或配置秘密。业务错误对外返回可操作说明；内部异常用 requestId 关联受控日志。
- 联系方式和内部内容在返回 VO 时按资源权限过滤，不能先发送给前端再隐藏。
- 附件采用随机存储键与私有目录，单文件最大 20 MiB，数量上限 5。扩展名/MIME、用途、所有者、绑定状态由后端校验；不信任客户端 Content-Type。
- 下载必须鉴权，不暴露物理路径，不允许路径穿越、任意外部 URL 下载或执行上传内容；删除也需重新检查权限与状态。
- 生产代理与上传大小限制保持一致，上传和日志目录按最小必要权限配置。

## 8. 数据库与迁移

结构由 Flyway SQL 文件演进。已执行的 V1～V8 不修改、重命名或删除；后续结构变更新增唯一版本迁移。不在生产手工改表绕过历史，不执行 clean 修复校验失败。

主键、唯一键、外键/检查约束和索引以现有迁移为准。金额用 BigDecimal/定点数，时间点保存 UTC。新增索引依据真实查询评估；数据库异常不能暴露表结构或秘密。

迁移在独立 MySQL 8.4 测试库验证空库及从上一版本增量升级。H2 测试可验证部分事务和竞争，但不能代表 MySQL 方言、锁和索引完全兼容。当前 CI 没有自动启动 MySQL 进行全量迁移验收，发布前须补充环境证据。

优先采用向后兼容迁移；数据库变更与应用回退兼容性必须记录。备份与恢复见[服务器准备指南](持续部署服务器准备指南.md)。

## 9. 本地检查与 CI

在仓库根目录执行以下 PowerShell 命令，需先安装前端依赖：

```powershell
Push-Location backend
.\mvnw.cmd --batch-mode --no-transfer-progress clean verify
Pop-Location

Push-Location frontend
pnpm format:check
pnpm typecheck
pnpm lint
pnpm test
pnpm build
Pop-Location

python -B -m unittest discover -s deploy/ci/tests -v
python -B -m unittest discover -s deploy/server/tests -v
git diff --check
git diff --cached --check
```

遇到失败先修复再继续交付；PowerShell 中多个原生命令不会自动因前一条失败而停止，必须检查退出码。Windows 会跳过部分 Linux 锁、权限和 Bash 测试；本地未设置 TEST_RELEASE_DOCKER=1 时记录镜像集成测试可能跳过，不能记为通过。

[CI](../.github/workflows/ci.yml) 对任意 push、面向 main 的 PR 和手动运行执行：

| 检查名称                 | 当前内容                                                                       |
| ------------------------ | ------------------------------------------------------------------------------ |
| Backend / test           | JDK 21、Maven clean verify                                                     |
| Frontend / quality       | 格式、类型、ESLint、Vitest、生产构建                                           |
| Configuration / validate | 三套 Compose 解析、Bash 语法、发布记录与假 Docker 测试、systemd 单元及部署约束 |

CI 不自动提供真实业务浏览器验收、MySQL 迁移演练、SMTP 送达或生产恢复证据。测试应针对实际风险覆盖正常、错误、无权限、状态与并发路径，不为纯文档变更新写重复实现的测试；纯文档核验链接、代码入口、命令及格式即可。

## 10. 发布、配置与运维

- 应用镜像由[发布工作流](../.github/workflows/publish-images.yml)产生；main push CI 成功后发布成对摘要记录，服务器拉取端独立执行。流程详见[服务器准备指南](持续部署服务器准备指南.md)。
- 本地开发、源码构建生产栈和既有服务器拉取栈使用不同入口，不把命名卷与现有绑定目录混用。
- 示例环境文件可提交，实际 env、SMTP credential 和本地配置不得提交。修改容器环境需要重新创建，单纯 restart 不更新环境。
- Test-ReleaseReadiness.ps1 检查源码构建生产栈的配置、Git 和前后端质量；它不检查服务器拉取状态、SMTP 送达、真实迁移、systemd 或恢复能力。不能把脚本成功当作完整上线验收。
- 生产只公开入口代理，数据库和后端不直接暴露公网；代理链、HTTPS、健康检查和卷权限需现场核对。
- 控制脚本和 systemd 更新单独审核安装。数据库迁移不自动反向执行；CD 失败先停调度并检查状态，禁止删除锁/状态或全局清理 Docker。
- 数据库和附件需要时间对应的可恢复备份，异机副本及恢复演练不能由本地 retention 代替。

## 11. 文档维护与交付

每类信息维护一个主要位置，其他页面链接过去：

| 改动                   | 同步文档                   |
| ---------------------- | -------------------------- |
| 能力、字段、权限、状态 | 需求文档与相关验收清单     |
| 页面、组件、视觉       | 前端实现说明与设计决策     |
| 命令、环境、依赖       | README、本文与实际配置模板 |
| 部署或控制程序         | 服务器准备/CD 专项说明     |
| 可交付功能变化         | CHANGELOG                  |

文档只写可从代码或明确记录验证的事实；计划、代码完成、测试通过、生产启用分开表述。删文档前先迁移仍有效的独有内容并更新所有引用。验收清单可重复使用，不保存过时分支名、对话交接语或未证实的“已上线”。

PR 至少说明：解决的问题与最终行为、验证及未执行项、配置/迁移影响、已知限制。现场发布另按流程书记录提交、digest、环境、备份与恢复结果。
