# 需求方使用指南

> 更新：2026-09-12。适用于希望获得网站、程序、数据或设备技术支持的校内师生、社团和授权用户。

## 1. 获取账号与登录

从首页进入登录。平台开放注册时，可以填写账号、称呼、邮箱和密码注册，成功后返回登录；若要求特定邮箱后缀，请使用符合要求的邮箱。注册关闭时，通过页面提示联系管理员开通需求方账号。

普通密码需为 8～72 字符并包含字母和数字，中文或特殊字符还受编码长度限制，以页面提示为准。忘记密码时进入“忘记密码”：功能开启后输入账号已绑定的邮箱，打开邮件链接设置新密码。链接默认有效 15 分钟且只能使用一次，重新申请后旧链接失效，成功后需重新登录。功能未开放或无法访问绑定邮箱时联系管理员。

连续输错密码可能暂时锁定账号，默认 5 次后锁定 15 分钟。不要反复尝试或向他人发送密码、邮件重置链接。

## 2. 什么需求适合提交

可以说明网站或内部工具建设、程序异常与重复工作自动化、数据整理分析、软件环境及设备网络问题。无需先懂编程，也不必自己确定技术方案。分类不确定时选择最接近的一项，具体承接范围由团队评估。

提交不代表已经承接。紧急程度和期望日期用于帮助评估，不等于团队已承诺工期。费用、采购、合同、发票及组织审批需另行处理。

## 3. 准备与提交

准备四类信息：为什么需要、希望得到什么、什么时候使用、有哪些参考材料。再填写分类、联系方式并确认内容真实有效。

> 例如：学院下月举办开放日，目前用群接龙收集报名，信息容易缺失。希望参与者在手机上填写，负责人可以导出名单。预计 9 月 20 日开始使用，已有字段表格作为附件。

避免只写“做个系统”或“越快越好”。不完整时先保存草稿；只有提交成功才进入技术组评估。草稿不会自动离线保存，离页前确认保存结果。

附件单文件最多 20 MiB，数量上限为 5，实际允许类型以上传提示为准。不要上传账号密码、密钥、涉密内容或无授权的个人信息。

## 4. 当前状态与下一步

| 页面状态      | 含义                     | 你要做什么                         |
| ------------- | ------------------------ | ---------------------------------- |
| 草稿          | 尚未发送给团队           | 继续编辑后提交，或取消             |
| 待评估        | 团队判断范围与可行性     | 留意站内通知                       |
| 待补充        | 团队提出了具体问题       | 按编辑页最新要求补充并提交         |
| 待分配        | 已确认可承接，待安排人员 | 等待负责人安排                     |
| 处理中        | 团队执行并记录进展       | 查看详情，有待确认问题时回复       |
| 待验收        | 已提供成果               | 检查成果，通过或说明需要调整的内容 |
| 已完成        | 已确认成果               | 查看历史记录                       |
| 已驳回/已取消 | 当前需求不继续           | 查看原因，必要时与团队沟通         |

首页“待我处理”汇集草稿、待补充和待验收事项。也可从“我的需求”筛选并打开详情，查看公开评估、负责人、预计时间、进度、附件和交付记录。没有业务全流程邮件提醒，请留意站内通知。

待补充编辑页会显示团队最新公开要求；单独保存仍然是待补充，重新提交后才回到待评估。补充不是拒绝，按问题逐项说明即可。

## 5. 保存或提交失败怎么办

| 提示/情况                        | 处理方式                                                                 |
| -------------------------------- | ------------------------------------------------------------------------ |
| 内容已保存，但提交结果尚未确认   | 保留页面，先核对详情状态，按提示重试提交                                 |
| 内容已被其他操作更新             | 先复制需要保留的输入，查看最新详情，再决定如何修改；不要覆盖他人的新版本 |
| 分类或补充要求加载失败           | 点击对应重试，已填写内容不会因此清空                                     |
| 新建请求超时、不确定是否提交成功 | 先去“我的需求”核对，避免重复创建                                         |
| 当前状态不可编辑或无权访问       | 返回详情查看最新状态，必要时联系团队                                     |

从草稿、待评估、待补充和待分配状态可以取消自己的需求；进入处理或待验收后，联系负责人或管理员处理。平台当前没有直接删除需求的功能。

## 6. 验收成果

打开需求详情的交付验收区域，按原始场景检查：主要操作是否可用，结果是否完整，文件和链接是否可打开，使用说明及限制是否清楚。

符合预期则通过验收；需要调整时写出操作步骤、实际结果、期望结果及可复现样例，需求返回处理中。每次验收针对最新交付，后续重新交付后再检查。验收或取消有实际业务影响，请确认所选需求及内容。
