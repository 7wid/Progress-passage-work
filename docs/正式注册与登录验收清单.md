# 正式注册与登录验收清单

> 更新：2026-09-12。每次记录环境、提交、执行时间及结果；本文不表示线上已经验收。

## 1. 配置与前置条件

生产注册默认关闭。需要开放时在实际部署环境文件设置：

```env
APP_REGISTRATION_ENABLED=true
APP_REGISTRATION_EMAIL_SUFFIX=
APP_LOGIN_SECURITY_MAX_FAILED_ATTEMPTS=5
APP_LOGIN_SECURITY_LOCK_DURATION=15m
```

限校内使用时填写组织真实邮箱后缀。保持 HTTPS、SESSION_COOKIE_SECURE=true 和准确的 APP_WEB_ORIGIN。已有 env 不会随应用镜像自动改变，修改后须重新创建后端；restart 不更新环境。

由拉取代理管理的服务器，人工操作前先停 timer 并等待正在运行的 service 完成，备份配置和基线。重建后核对健康和代理状态，按[拉取端恢复说明](CD-pull-agent.md)协调，不能删除状态或重新初始化绕过保护。该要求也适用于紧急关闭注册。

当前注册不发送预激活邮件，邮箱后缀限制不能证明归属。找回密码时的邮箱控制权验证见[邮箱找回密码部署与验收](邮箱找回密码部署与验收.md)，该开关独立于注册。

## 2. 自动化与只读检查

先执行[项目开发规范](项目开发规范.md)中的后端 clean verify、前端格式/类型/lint/测试/构建和 Compose 校验。不要在日志打印 env、密码、Session Cookie 或 CSRF Token。

对已批准的环境执行只读检查（部署到其他域名时替换地址）：

```powershell
curl.exe --fail https://job.gxutech.xyz/actuator/health
curl.exe --fail https://job.gxutech.xyz/api/v1/users/registration
```

- [ ] 健康为 UP，注册状态与所选开关一致，emailSuffix 与配置一致。
- [ ] 真实 HTTPS 入口有预期安全响应头；会话 Cookie 含 Secure、HttpOnly、SameSite=Lax。
- [ ] 注册关闭时首页、登录和注册页提供获取账号指引，不误导用户直接注册。

## 3. 注册与管理员开通

使用专用验收账号及有权访问的邮箱，不使用真实管理员或他人的个人信息。

- [ ] 登录页可进入注册；必填、邮箱、手机号、密码强度和确认密码错误在字段旁显示。
- [ ] 账号 3～64 字符、首尾字母或数字，允许的中间字符与后端一致；密码 8～72 字符、含字母数字且 UTF-8 不超过 72 字节。
- [ ] 邮箱后缀限制前后端一致，直接绕过前端请求仍被拒绝。
- [ ] 注册成功回到登录并有提示；重复账号或邮箱不创建第二条记录，也不指出是哪项已存在。
- [ ] 新账号角色固定 REQUESTER、状态 ACTIVE，数据库仅保存 BCrypt 哈希。
- [ ] 管理员可在需求方账号管理开通账号、查看列表和启停用；普通成员和需求方不能访问管理 API。
- [ ] 注册失败或网络错误有恢复入口，输入与加载状态处理正确。

## 4. 登录与会话

- [ ] 账号首尾空格与大小写规范化后可登录，密码原文不会自动裁剪。
- [ ] 登录后刷新保持会话，目标回跳受站内路径检查保护。
- [ ] 退出后旧会话不能访问受保护接口；停用账号后不能继续使用已有会话。
- [ ] 用专门测试账号按实际失败阈值验证锁定及到期恢复；默认 5 次、15 分钟，不对生产管理员执行。
- [ ] 成功登录清除历史失败次数，错误响应不泄露账号存在性。
- [ ] 修改密码要求旧密码，其他已登录会话失效。
- [ ] 写请求缺失/错误 CSRF 令牌被拒绝；日志没有密码、会话 ID 和 CSRF 值。

## 5. 关闭与结果记录

异常时设置 APP_REGISTRATION_ENABLED=false，按上述受控配置流程重新创建后端并确认状态接口关闭。关闭新注册不删除账号、不自动停用已有用户；停用使用管理功能并保留审计。

验收项分别记录通过、失败或未执行。保留脱敏证据与失败复现步骤，后续发布仍须核对[项目流程书](项目流程书.md)中的部署和恢复条件。
