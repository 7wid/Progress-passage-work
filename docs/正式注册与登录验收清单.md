# 正式注册与登录验收清单

本文用于发布需求方自助注册与正式登录能力。不要在命令输出、截图、工单或聊天中暴露 `.env.prod`、数据库密码、管理员密码、Session Cookie 或 CSRF Token。

邮箱验证与忘记密码重置的配置、迁移和验收见 [邮箱找回密码部署与验收](邮箱找回密码部署与验收.md)。

## 1. 发布前配置

1. 备份数据库和当前生产环境配置，并确认可以恢复。
2. 在服务器实际使用的 `.env.prod` 中设置：

   ```env
   APP_REGISTRATION_ENABLED=true
   APP_REGISTRATION_EMAIL_SUFFIX=
   APP_LOGIN_SECURITY_MAX_FAILED_ATTEMPTS=5
   APP_LOGIN_SECURITY_LOCK_DURATION=15m
   ```

3. 如果服务只面向特定学校或组织，设置准确的邮箱后缀，例如 `@example.edu.cn`；不要照抄示例域名。
4. 保持 `SESSION_COOKIE_SECURE=true`，并确认公开入口全程使用 HTTPS。
5. 已部署服务器的旧配置不会被镜像内默认值覆盖。修改环境文件后必须按现有持续部署流程重建或重新创建后端容器。

## 2. 自动化质量门禁

在干净的功能分支执行：

```powershell
Set-Location backend
.\mvnw.cmd test
Set-Location ..\frontend
pnpm.cmd run format:check
pnpm.cmd run lint
pnpm.cmd run typecheck
pnpm.cmd run test
pnpm.cmd run build
```

还应校验实际使用的 Compose 配置，但不要把展开后的环境变量输出到日志。

## 3. 线上只读检查

```powershell
curl.exe --fail https://job.gxutech.xyz/actuator/health
curl.exe --fail https://job.gxutech.xyz/api/v1/users/registration
```

检查项：

- 健康检查返回 `UP`。
- 注册状态返回 `enabled: true`。
- 如果配置了邮箱后缀，接口返回值与配置完全一致。
- HTTPS 响应包含 HSTS，Session Cookie 带 `Secure`、`HttpOnly` 和 `SameSite=Lax`。

## 4. 注册闭环

使用专门的验收账号，不使用真实管理员或他人的个人信息。

1. 从 `/login` 可以进入 `/register`。
2. 空字段、错误邮箱、弱密码、两次密码不一致和无效手机号均在对应字段旁提示。
3. 如果限制了邮箱后缀，其他后缀在前端和后端都会被拒绝。
4. 注册成功后回到登录页并显示成功提示。
5. 重复账号或邮箱不会创建第二条用户记录，也不会暴露具体是哪一项已存在。
6. 新用户角色固定为 `REQUESTER`，状态为 `ACTIVE`，数据库只保存 BCrypt 哈希而不是明文密码。

## 5. 登录与会话闭环

1. 账号前后空格和大小写不会影响登录，密码原文不会被自动裁剪或改写。
2. 登录后刷新页面仍保持会话，访问原目标地址时只允许站内路径。
3. 退出后旧 Session 不能继续访问受保护接口。
4. 使用专门的锁定测试账号连续输入 5 次错误密码，确认随后无法登录；等待 15 分钟后可再次尝试。
5. 正确登录会清除历史失败次数。不要用生产管理员账号执行锁定测试。
6. 日志和审计记录不得出现账号输入值、密码、Session ID 或 CSRF Token。

## 6. 回退

发现注册滥用或异常时，先将生产配置改为：

```env
APP_REGISTRATION_ENABLED=false
```

随后仅重建后端容器并确认注册状态接口返回 `enabled: false`。该操作只关闭新注册，不删除已有账号；涉及账号停用时应使用管理功能并保留审计记录。
