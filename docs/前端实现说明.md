# 前端实现说明

> 文档版本：V1.0
> 适用范围：`frontend/` 目录
> 当前实现日期：2026-08-17
> 技术基线：Vue 3 + TypeScript + Vite + Element Plus + Lucide

---

## 1. 文档定位

本文记录前端当前已经落地的架构、页面、视觉规范和验证方式。业务规则以《需求文档》为准，通用编码要求以《项目开发规范》为准；当本文与代码不一致时，应先确认代码变更是否已经验收，再在同一合并请求中更新本文。

设计细节的参考源为：

- `frontend/src/styles/index.css`：运行时设计令牌和全局组件规则，是实际代码的事实来源。
- `design-system/tech-request-operations/MASTER.md`：设计决策和后续页面扩展的参考。
- 各 Vue 文件中的 `<style scoped>`：页面或组件独有样式。

## 2. 技术栈

| 用途 | 当前方案 | 约束 |
|---|---|---|
| 框架 | Vue 3 + TypeScript | 使用组合式 API 和 `<script setup>` |
| 构建 | Vite | 开发端口默认 `5173`，`/api` 代理到后端 |
| 路由 | Vue Router | 页面按路由懒加载，守卫处理登录和角色限制 |
| 全局状态 | Pinia | 当前仅保存认证和通知等跨页面状态 |
| UI 组件 | Element Plus | 表单、表格、分页、弹窗和反馈组件 |
| 图标 | `@lucide/vue` | 不使用 Emoji 或手写 SVG 代替通用操作图标 |
| HTTP | Axios | 请求统一放在 `src/api`，携带服务端会话 Cookie |
| 测试 | Vitest + Vue Test Utils | API、Store、组件和主要页面测试 |
| 质量检查 | ESLint + Prettier + `vue-tsc` | 合并前必须全部通过 |

运行环境要求见 `frontend/package.json`：Node.js `>=22.12.0`，pnpm `>=10`。

## 3. 启动与入口

```powershell
Set-Location frontend
pnpm install --frozen-lockfile
pnpm dev
```

默认访问地址为 `http://127.0.0.1:5173` 或 Vite 输出的本机地址。

启动链路：

```text
src/main.ts
  -> 创建 Vue、Pinia、Vue Router、Element Plus
  -> App.vue
  -> router/index.ts
  -> 公共认证页面或受保护的 AppLayout
```

## 4. 目录职责

```text
frontend/src/
├─ api/          # Axios 请求函数及对应测试
├─ components/   # 按 admin、assignment、common 等业务域组织的组件
├─ layouts/      # AuthLayout 与 AppLayout
├─ router/       # 路由表、懒加载和权限守卫
├─ stores/       # 认证、通知等跨页面状态
├─ styles/       # 全局设计令牌和 Element Plus 覆盖
├─ types/        # 与接口契约对应的 TypeScript 类型
└─ views/        # 路由页面
```

没有实现内容时不创建空的 `assets`、`composables` 或 `utils` 目录，也不使用 `.gitkeep` 保留空目录。新增目录必须有明确职责和实际文件。

## 5. 布局与导航

### 5.1 认证布局

`AuthLayout.vue` 由登录和注册页面复用：

- 桌面端使用深蓝品牌区和表单区双栏布局。
- 品牌区使用 Lucide 图标表达“提交、处理、完成”流程。
- 窄屏收敛为单栏，并隐藏非关键装饰信息。
- 登录和注册保留各自表单逻辑，不复制布局代码。

### 5.2 应用布局

`AppLayout.vue` 提供受保护页面的统一外壳：

- 左侧为按角色过滤的持久导航。
- 顶部提供当前页面上下文、全局需求搜索、提交需求、通知和用户菜单。
- 小于 `900px` 时侧栏变为抽屉，通过遮罩或关闭按钮退出。
- 页面内容通过 Vue `Transition` 切换。
- 侧栏不提供收起状态，避免维护重复的桌面和移动端布局分支。

导航只负责可发现性，权限仍由路由守卫和后端共同校验。

## 7. 视觉系统

### 7.1 颜色

主色为蓝色，语义色不能替代主操作色：

| 令牌 | 当前值 | 用途 |
|---|---|---|
| `--color-primary` | `#2563EB` | 主按钮、当前导航、链接和图表主序列 |
| `--color-primary-strong` | `#1D4ED8` | 悬停和高强调文本 |
| `--color-primary-soft` | `#EFF6FF` | 选中背景和蓝色图标底色 |
| `--color-success` | `#059669` | 成功、完成 |
| `--color-warning` | `#D97706` | 警告、时效和较急状态 |
| `--color-danger` | `#DC2626` | 错误、危险和逾期 |
| `--color-purple` | `#7C3AED` | 次级统计维度，不作为主操作色 |

组件优先引用语义令牌，不在页面中重新定义旧 Element Plus 蓝色或绿色。状态必须同时显示文字或图标，不能只依靠颜色。

### 7.2 字体、圆角和阴影

- 中文字体使用系统字体栈，避免额外字体下载影响首屏。
- 页面标题、正文和辅助文字使用统一层级，不按视口宽度缩放字号。
- 常用圆角为 `6px`、`8px` 和 `12px`。
- 普通卡片只使用细边框和轻阴影；高层阴影保留给抽屉、弹窗等覆盖层。
- 页面不使用玻璃拟态、紫蓝渐变、装饰光斑或卡片嵌套。

### 7.3 图标

- 通用操作和导航统一使用 Lucide 线性图标。
- 图标与可见文字并列时添加 `aria-hidden="true"`。
- 仅图标按钮必须提供 `aria-label` 和必要的 `title`。
- 同一层级保持接近的尺寸和笔画粗细。

## 8. 页面与组件模式

- 路由页面根节点通常使用 `.page`，页首使用 `.page__header`。
- 一个页面或区域只保留一个主要蓝色操作，其余操作使用普通或链接按钮。
- 首页保留状态指标和最近需求，不重复提供与侧栏相同的快捷入口面板。
- 列表和工作台使用服务端分页；整行可点击时，行内按钮必须阻止冒泡。
- 表单提供可见标签、加载状态和具体错误反馈。
- 图表使用文字标题、坐标和可读的空状态；统计颜色保持可解释。
- 跨页面复用的业务 UI 放在 `components`，只在单页使用的样式保留为 scoped 样式。

## 9. 状态与请求约定

- 认证信息由 `stores/auth.ts` 管理，初始化时请求当前用户。
- 通知未读数和并发标记由 `stores/notifications.ts` 管理，退出登录时重置。
- 页面筛选、分页和弹窗通常使用局部状态，不放进 Pinia。
- API 调用只能从 `src/api` 发起，页面不直接拼接 Axios 请求。
- 可能重复触发的列表请求使用序号忽略过期响应，避免旧请求覆盖新筛选结果。
- 前端隐藏按钮不构成权限控制，后端必须独立鉴权。

## 10. 动效与响应式

允许的主要动效：

- 路由内容使用短距离淡入淡出。
- 首页或统计页的一组摘要指标允许 `45ms` 左右错峰入场。
- 按钮按下可使用轻微缩放反馈。

动画只改变 `transform` 和 `opacity`，不得依赖动画结束事件完成业务状态。全局 `prefers-reduced-motion` 会把动画缩短到近似静态。

响应式检查至少覆盖：

- `375px` 手机宽度。
- `768px` 平板或横屏。
- `1024px` 小型桌面。
- `1440px` 常规桌面。

全局最小支持宽度为 `320px`。宽表格允许在内容区域内合理滚动，页面本身不得产生无意义的横向溢出。

## 11. 开发与验证命令

在 `frontend` 目录执行：

```powershell
pnpm format:check
pnpm typecheck
pnpm lint
pnpm test
pnpm build
```

当前基线（2026-08-17）为 34 个测试文件、111 项测试通过。测试数量会随功能变化，合并要求是全部通过，而不是维持固定数量。

生产构建目前仍会提示主包超过 Vite 默认的 `500 kB` 建议值。路由页面已经按需加载；后续如优化主包，应先分析 Element Plus 的全量注册和公共依赖，再决定按需引入或拆分 vendor chunk，不得只提高告警阈值掩盖问题。
