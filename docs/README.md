# 项目文档导航

本项目首先服务于提出需求的人。阅读文档时，请从“我要解决什么问题”开始，而不是从技术架构开始。

## 我是需求方

建议按以下顺序阅读：

1. [需求方使用指南](需求方使用指南.md)：如何判断是否适合提交、怎样描述问题、如何查看进度和验收成果。
2. [项目流程书](项目流程书.md)：团队会怎样评估、承接、处理和交付，以及每个阶段需要你做什么。
3. [需求文档](需求文档.md)：产品能力、角色权限和完整业务规则。

## 我是技术组成员或管理员

- [项目流程书](项目流程书.md)：协作职责、状态流转和异常处理。
- [前端实现说明](前端实现说明.md)：页面架构、设计语言、动效和验证方法。
- [项目开发规范](项目开发规范.md)：编码、测试、安全、Git 和交付标准。
- [P1 成员负载分析验收清单](P1成员负载分析验收清单.md)
- [P1 成员推荐验收清单](P1成员推荐验收清单.md)

## 文档共同原则

- 面向需求方的页面和说明优先使用日常语言；技术名词必须附上“这对你意味着什么”。
- 状态说明必须同时回答“现在发生了什么、是否需要我处理、下一步是什么”。
- 不承诺未经团队确认的工期、能力和数据，不编造服务指标或成员履历。
- 业务规则以《需求文档》为准，工程实施以《项目开发规范》为准，运行中的代码和接口契约需要与文档同步更新。
