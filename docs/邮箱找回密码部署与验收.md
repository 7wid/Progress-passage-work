# 邮箱找回密码部署与验收

本次在已有注册、登录和账号锁定的基础上增加邮箱验证重置密码，适用于所有已绑定邮箱且状态为 `ACTIVE` 的账号。短信供应商尚未接入；邮箱验证已覆盖自助找回需求。注册邮箱目前不要求预先激活，找回时由收件人持有的随机链接验证邮箱控制权。邮箱后缀限制不等同于邮箱验证。

## 生产配置

沿用服务器现有 CI 镜像发布流程，在服务器实际 `.env.prod` 中配置以下变量。不要在服务器临时构建源码，也不要把 SMTP 授权码提交到 Git 或贴入日志。

```env
APP_PASSWORD_RECOVERY_ENABLED=true
APP_PASSWORD_RECOVERY_FROM=security@your-domain.example
APP_PASSWORD_RECOVERY_RESET_URL=https://job.gxutech.xyz/reset-password
APP_PASSWORD_RECOVERY_TOKEN_TTL=15m
SMTP_HOST=smtp.your-provider.example
SMTP_PORT=587
SMTP_USERNAME=your-smtp-account
SMTP_PASSWORD=your-provider-app-password
SMTP_AUTH=true
SMTP_STARTTLS_ENABLED=true
SMTP_SSL_ENABLED=false
```

- 将示例邮箱、主机、账号替换成已授权的 SMTP 服务信息。发件地址应与供应商授权的地址/域名一致，按供应商要求配置 SPF、DKIM 和 DMARC，并验证邮件可达性。
- 587 使用强制 STARTTLS；465 使用 `SMTP_PORT=465`、`SMTP_STARTTLS_ENABLED=false`、`SMTP_SSL_ENABLED=true`。非本机 SMTP 禁止明文连接，证书主机名校验默认开启。
- 连接、读取、写入超时均为 5 秒。使用专用、最小权限的发信账号；生产 `.env.prod` 设置为仅运维用户可读（如 `chmod 600`）。
- 重置页面地址来自受信任的静态配置，不从客户端 `Host` 或转发头拼接。只能配置无查询参数/片段的 HTTPS `/reset-password` 地址；HTTP 仅允许 `localhost` 或 `127.0.0.1` 本机测试。
- 未配置邮件时功能默认关闭，页面显示联系管理员。开启后缺少发件地址、SMTP 主机、有效地址或有效期不在 5～30 分钟范围内，会阻止启动。
- 此开关独立于 `APP_REGISTRATION_ENABLED`；已有账号即使不开放自助注册也可以找回密码。

两个生产 Compose 清单均已透传上述变量。配置变更后重新创建后端容器；仅 `restart` 不会更新容器环境。服务器清单需要同时加载 `.env.prod` 与 `release.env`，例如在部署目录执行：

```sh
docker compose --env-file .env.prod --env-file release.env config --quiet
docker compose --env-file .env.prod --env-file release.env up -d --no-deps --force-recreate backend
```

不要使用会打印展开后密钥的 `docker compose config`。先发布对应版本的前后端镜像并核实健康检查，再开放功能。

## 数据库与会话

- Flyway V8 增量迁移增加 `password_reset_token`、`auth_rate_limit` 和 `sys_user.password_reset_at`，不修改历史迁移。发布前备份 MySQL，迁移由单一发布实例先行执行。
- 重置凭证使用 256 位安全随机数，数据库只存 SHA-256 摘要，默认有效 15 分钟；一人只保留最新凭证。
- 链接包含 URL fragment `#token=...`，不会随页面 GET 请求或 Referer 发送给服务器。前端读取后清除地址栏，只在组件内存保留；刷新后需重新打开邮件。前端不写 Cookie、localStorage 或 sessionStorage。
- 重置时同时锁定用户和凭证，密码更新、凭证删除及审计处于同一事务；并发请求只有一个成功。邮箱或密码在发信后改变、账号停用、链接过期或已经使用，均拒绝重置。
- 密码沿用 BCrypt 强度与 UTF-8 72 字节限制，不能与原密码相同。重置成功会清除失败计数和临时锁定，不会自动登录。
- 事务提交后删除所有旧 Session，并异步发送密码变更通知。每次受保护请求还会核验登录时间是否晚于密码重置时间，作为旧 Session 删除失败时的兜底。
- 未绑定邮箱/无法访问邮箱的用户需联系管理员通过独立渠道核验身份后恢复，不根据前端传入的新邮箱发送重置链接。

## 防滥用与运行

发送申请始终先经过统一限流，再异步查找账号。未知邮箱、停用账号、邮箱自身限流均返回相同的 HTTP 202 文案，避免通过响应内容或 SMTP 耗时枚举账号。202 表示申请已处理，不承诺邮件已经送达。

| 范围 | 默认限制 |
| --- | --- |
| 发送申请，所有实例合计 | 500 次/固定小时窗口 |
| 发送申请，单 IP | 20 次/固定 15 分钟窗口 |
| 发送申请，单邮箱 | 5 次/固定小时窗口，且相邻受理至少间隔 60 秒 |
| 重置提交，所有实例合计 | 3000 次/固定小时窗口 |
| 重置提交，单 IP | 30 次/固定 15 分钟窗口 |

限流使用数据库条件更新，多实例共享；全局/IP 超限返回 429。固定窗口边界允许前后两个窗口各自额度，60 秒邮箱间隔独立校验。每小时分批清理过期数据，每轮最多约一万行，避免长时间持锁。以上阈值集中定义在 `PasswordRecoveryService`，需要根据真实流量调整时应经过评审。

邮件使用专用 2 线程、50 项有界内存队列，SMTP 调用不占用数据库事务。队列满时返回 503；发送失败会删除该次凭证，仅记录异常类型，不记录邮箱、邮件正文或链接。停机最多等待 20 秒处理队列。进程崩溃可能丢失尚未发送的任务，本版本不提供持久化邮件重试；用户 60 秒后可重新申请。变更通知失败不撤销已完成的密码重置。

SMTP 不纳入应用存活健康检查，防止邮件供应商故障导致整个业务服务被反复重启。服务状态接口只表示功能已配置开启，不表示即时送达能力；应监测发信失败日志并定期以专用邮箱验收邮件可达性。

公网流量必须经过可信 HTTPS 反向代理，后端与 MySQL 不开放公网端口。最外层代理应覆盖客户端提供的 `Forwarded` / `X-Forwarded-For` / `X-Real-IP`，仅信任已知代理链；不要直接把未经清洗的客户端头交给 Spring 的转发头处理。防火墙限制前端内部端口只能由入口代理访问。入口代理同时配置合理的请求体大小、连接数及 IP 限速，监测 429/503 和发信失败事件。

## 验证

1. 运行后端 `./mvnw test`、前端类型检查、Lint、Vitest、构建和本次文件格式检查。数据库并发/回滚测试使用 H2 MySQL 模式；正式发布仍需在测试 MySQL 8.4 上验证 Flyway V8 和并发流程，不能用 H2 代替生产数据库验收。
2. 只读检查 `/actuator/health` 为 `UP`，`GET /api/v1/auth/password-recovery` 返回 `enabled: true, channel: EMAIL`；响应不得缓存。
3. 使用有权访问邮箱的专用测试账号，从登录页进入“忘记密码”，验证邮件中的域名、发件人、链接有效期、垃圾邮箱投递情况。
4. 对未注册邮箱发起相同申请，响应内容与已注册邮箱相同；请求未带 CSRF 时返回 403。不得使用他人邮箱验收。
5. 打开链接，确认地址栏凭证被清除；错误的确认密码、弱密码、超长 UTF-8 密码不提交。
6. 完成重置后跳转登录页，新密码可登录、旧密码不可登录；原设备会话访问受保护 API 返回 401。确认收到密码变更通知，审计中有 `PASSWORD_RESET`。
7. 再次使用原链接、过期链接或重新申请前的旧链接，均不能重置。发信后更改绑定邮箱/密码或停用账号，再使用链接也应失败。
8. 在测试环境并发使用同一链接，仅一次成功；模拟审计写入失败，密码和凭证操作应一起回滚。用测试账号验证发送间隔及 429，不对生产管理员做锁定/压力测试。
9. 在测试环境模拟 SMTP 断连，HTTP 不等待 SMTP，记录无敏感信息，稍后重新申请可恢复。检查环境变量更新后邮件配置确实生效。

## 关闭与回退

紧急关闭时设置 `APP_PASSWORD_RECOVERY_ENABLED=false` 并重建后端容器，已有登录不受影响，未使用链接也不能重置。优先关闭功能而非回退到没有会话撤销校验的旧应用版本。

V8 为增量兼容迁移，应用回退时保留新表/字段和 Flyway 历史，不执行自动删表回滚。如果必须退到 V8 之前的应用版本，须按运维流程使所有旧会话失效，防止旧代码忽略密码重置时间；不要通过改写 Flyway 校验和绕过迁移检查。
